# REL-20261127 — standalone worker cache-context defect

## Summary and impact

The [27 November background-jobs release record](../../BACKGROUND_JOBS_RELEASE_20261127.md)
reports that initial worker smoke validation found a standalone Next.js cache
error. Worker configuration/source was fixed and synthetic recovery/failure checks
rerun successfully.

This is a retrospective release-validation defect, not proof of a student-facing
outage. Exact event times, affected deployment IDs, stack trace, root-cause commit,
and any real-user impact were not captured in the cited record.

## Timeline

All events are dated 27 November 2026; exact times unknown:

1. Queue release and worker validation performed.
2. Initial smoke test detects standalone Next.js cache error.
3. Worker configuration/source corrected.
4. Recovery and permanent-failure synthetic checks rerun successfully.
5. Source records synthetic-data cleanup and all three Railway app services running.

This sequence is reported by the release note, not independently replayed during
this documentation task.

## Cause, response, and limits

Source attributes the failure to a standalone worker lacking Next.js request/cache
context. Recorded mitigation disables Next.js caching for that worker.
[Background-job design](../../BACKGROUND_JOBS.md) places cache revalidation in
Next.js when the dashboard observes completed work, not in standalone processes.

Recorded successful checks include existing-pack reuse with one final saved pack,
terminal job outcomes, safe failure messages, and persistent unread notifications.
These are synthetic checks. The source explicitly leaves real Canvas ingestion,
fresh LLM generation, browser navigation, long-running recovery, and notification
UI acceptance unverified.

## Lessons and follow-up

Framework-context dependencies must be tested in the actual worker runtime,
not only web-route unit tests. Public health checks do not exercise queue execution.
